# check_design.py

The design pair of one site: `DESIGN.md` against the site's CSS (plan 0.4 B.7.3).

- **Inputs:** `--site <site design folder>`; optional `--css` (repeatable, overrides `site.yaml`), `--tokens`, `--deploy-root`, `--json FILE` (never inside the site design folder: ERROR 2).
- **Modes:** `--verify` (default) writes nothing; `--issue` (which refuses `--css`, `--tokens` and `--deploy-root`) also checks the owner's approval and writes `ready.json` on PASS. Approval: `HEAD` resolved once to one commit; every file of the folder except `ready.json` equals its committed bytes there: the bytes the checks read against `git cat-file blob` of `git rev-parse <commit>:./<name>` (which runs no filter), equal after one explicit normalisation, CRLF to LF on both sides; a path whose attributes set `filter`, `ident` or `working-tree-encoding` (`git check-attr`) is not approved (INCOMPLETE: the repository could change its content). Read-only plumbing only (`rev-parse`, `cat-file`, `check-attr`): nothing writes the index or the object store, runs a filter or a hook. A receipt's blob id is the one `rev-parse` gives. The receipt is not issued when any input (profile, CSS, font) changed during the run, or when an existing `ready.json` is a link, a junction, a hard link or not a regular file; it is written to a new file in the folder and renamed into place. `--issue` prints the receipt's SHA-256 (for copies without a repository) and ends with the owner's step: commit `ready.json` now; approval counts only once it is committed (the consumers require the receipt to equal its committed blob; the CEO's decision of 2026-11-10).
- **Shape first:** `policy.yaml`'s whole shape (the type of every key of its schema, list items included) is checked before any entry is read; a wrong type anywhere is a named POL FAIL, and derived variables, token contrast and the policy's entries are then not read (never INTERNAL 4).
- **Stages:** P2 parse and schemas (strict YAML; typed tokens and component fields by what they resolve to; binding coverage both ways; empty bindings refused) → design-first regeneration of `tokens.css` → P1 trace (typed exact comparison of each binding; several different declarations of one binding, or of any variable it reaches through `var()` (the whole dependency graph, inheritance branches included), or an `!important` declaration anywhere in that graph, give INCOMPLETE; clamps, design-first too; component typography whole, family included, or along its inheritance chain; overrides) → derived variables (every context that declares one, overrides included, its references resolved: each paint allowed in each of its roles in each scheme that context applies to, never against the union of roles and schemes) → font-stack variables (declared in `:root`; the first family of every value an approved face family, as in a literal stack (the CEO's decision of 2026-11-12: one rule for every stack; a stack of generic families alone fails), and every other family an approved face family, a generic family or a family listed in the optional `fonts.fallback_families` (system fallbacks the policy allows; the CEO's decision of 2026-11-11), else FAIL naming the families and the list, or the first family when it is not an approved face: only a certified stack is accepted by `check_css.py`; A1 still judges the font that actually draws the text) → P3 token contrast (listed surfaces and the component's own background per scheme; dark pairs through aliases; the smallest size reached among the token's size and the trace map's font-size overrides for its selectors; `rem` at the root font size the site sets on `html` or `:root` (the smallest across media contexts; 16 px only when it sets none), an uncertain root size taking the stricter 4.5:1 threshold; baselines keyed by resolved colours, never worse) → policy (sections, types, floor, roles per scheme within its set, complete pairs, face files and their SHA-256, axe tags, tiers, extras, typed waivers; `buttons.paint` names palette tokens `{background, text}`, or `paint: selectors-only` says that primary buttons are identified by their selectors alone) → publication boundary → approval and receipt (`--issue`).
- **Outcomes:** PASS 0, FAIL 1, ERROR 2 (input or PyYAML unusable, site CSS unreadable, report not written or its destination a link or hard link), INCOMPLETE 3 (unsupported at-rule, ambiguous or importance-dependent declarations, an em size between 3:1 and 4.5:1, no deploy root, uncommitted files, content-changing attributes or inputs changed with `--issue`), INTERNAL 4. The report is written before the summary is printed, to a new file renamed into place (never through an existing link or hard link).
- **Limits:** declaration-level trace, not the effective cascade; CSS nesting, escaped property names, `@supports`, `@layer`, `@container`, `@scope`, `@import` give INCOMPLETE. Only a P2 failure stops the later stages; the others all report (more findings in one run; the outcome is the same).
- **Floor guards in the policy:** a reserved token named in `roles`, `headings`, `fills`, `buttons` or `scheme.pairs`, a token or extra with a reserved token's colour, a floor section `off` or empty, a floor assertion with a tier or waiver: FAIL.
