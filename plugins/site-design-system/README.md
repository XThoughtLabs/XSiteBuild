# site-design-system

The design system of any website, for agents: start one for a new site, derive one from an existing site's CSS, keep it in agreement with the CSS, and build and check pages, dashboard panels, report pages and images in it.

Status: 0.1.0, 2026-11-10 (plan 0.4; decision J1). Method only: no site's names, colours, fonts, paths or limits appear in the scripts or skills (a test checks this). Each site keeps its own private **site design folder**.

## Added in 0.1.0

Everything below (first version; see `CHANGELOG.md`).

## Changed after the outside audit, round 1 (0.1.0, not released)

The fixes of the two outside auditors' findings (46 IDs) are listed in `CHANGELOG.md`. The ones that change how the plugin is used: a staged copy of the site design folder with no Git repository is approved only when the consumer gets `--receipt-sha256 <SHA-256 of the issued ready.json>`; the receipt's schema is checked strictly; reports, snapshots and screenshots never go into the site design folder; `generate_css.py` writes LF and needs `policy.yaml` first; baselines record their resolved colours.

## Changed after HQ's check of the round-1 fixes (0.1.0, not released)

Listed in `CHANGELOG.md`. The ones that change how the plugin is used: A6 treats a paint change of any element of a frame during checking as INCOMPLETE (offsets and margins included); `check_css.py` accepts a `font` shorthand whose family is exactly one approved font-stack variable, expands at most 64 page-variable definitions per declaration and keeps at most 5,000 report items.

## Changed after the outside audit, round 2 (0.1.0, not released)

Listed in `CHANGELOG.md` (22 findings of Sol 6.1). The ones that change how the plugin is used:

- **Commit the receipt.** After `check_design.py --issue` the owner commits `ready.json` too; where a repository is reachable, approval counts only when the receipt read equals its committed blob (the CEO's decision). `--issue` ends with that instruction and prints the receipt's SHA-256 for copies without a repository.
- **A13 baseline.** `check_page.py --snapshot` prints the snapshot's SHA-256; `--kept FILE` counts only with `--kept-sha256 HEX` (that value). A13 compares the desktop light render (1280 px, light) only.
- **Screenshots.** The checker never resizes the viewport: it scrolls, and keeps a viewport-size capture at each scroll position it used (`<render>.png` at the top, `<render>-at-NNNNN.png` below), not a full-page capture.
- **Policy.** `buttons.paint` names tokens of the palette, or says `paint: selectors-only` (primary buttons identified by their selectors alone); `policy.yaml`'s whole shape is checked before any entry is read.
- **Design-first component stylesheets.** Once `site.yaml` names component stylesheets, `generate_css.py` binds every component field they define for the component's selector (the selector the trace map already names for it, else `.<component>`) to that selector; a field they do not define keeps its `--comp-…` variable; `size` always keeps its variable.
- **Outputs.** Every file the plugin writes goes to a new file put in place by rename; an existing name that is a link, a junction, a hard link or not a regular file is refused (ERROR 2), nothing written.

## Changed after HQ's check of the round-2 fixes (0.1.0, not released)

Listed in `CHANGELOG.md` (W1–W5 and two decisions of the CEO). The ones that change how the plugin is used:

- **Reader preferences.** After each render's evidence, `check_page.py` loads the page again, fresh, in the 11 other combinations of reduced motion, contrast and reduced transparency; a frame that paints differently in any of them gives its text A6 INCOMPLETE. A page whose painted result depends on those preferences no longer passes.
- **Fallback families.** The optional policy key `fonts.fallback_families` (a list of family names) lets a font-stack variable name system fallbacks after the approved face; A1 still fails text one of them actually draws.
- **Long text.** A text block taller or wider than the viewport stays A6 and A1 INCOMPLETE (the CEO's decision): split long text into paragraphs.

## Changed after HQ's check of CC-06 (0.1.0, not released)

Listed in `CHANGELOG.md` (X1–X4 and two decisions of the CEO). The ones that change how the plugin is used:

- **One list of paints.** Every comparison of paints (before and after the evidence, at each scroll offset, and in the fresh loads of the other reader preferences) reads one list, `PAINT_PROPS` in `scripts/pagejs.py`: shadows, borders, radii, outlines, background size and position, padding, sizes, border images and reflections are compared too, and the fresh loads also compare every element's border box. A page that draws any of them only for some readers no longer passes.
- **Shadows, outlines and border images near text.** Hit testing never sees them and axe ignores them: a `box-shadow`, `outline` or `border-image` that reaches a text run where it was checked gives its A6 INCOMPLETE (a card's own outer shadow never paints inside the card, so the card's text is not touched). A `blur()` or `drop-shadow()` filter, a `-webkit-box-reflect`, such a paint on a `::before` or `::after`, an unreadable shadow or one of a transformed element gives every text run of its frame INCOMPLETE.
- **Filters on text.** A `filter` or `backdrop-filter` on a text run's element or an ancestor gives A6 INCOMPLETE even where axe passed it (axe composes no filter; the CEO's decision).
- **Literal font stacks.** The families listed in `fonts.fallback_families` are allowed in a literal `font-family` stack of a page's own CSS too, after an approved face (the CEO's decision).

## Changed after HQ's check of CC-07 (0.1.0, not released)

Listed in `CHANGELOG.md` (U1, U2, Y1 and the CEO's decision on CC-07's Question 5). The ones that change how the plugin is used:

- **A blur counts only near itself.** A `blur()` or `drop-shadow()` filter on an element with no content of its own (a decorative shape: no child elements, text, `::before`/`::after`, own shadow, SVG or image) gives A6 INCOMPLETE only to the text within its reach: its box grown by 3 × blur, or moved by the drop shadow's offset and grown by 1.5 × its blur. Such a filter on anything else, or an animated one, still makes every text run of its frame INCOMPLETE.
- **Solid shadow bands are composed.** A solid inset shadow (no blur) of a text's element or an ancestor, such as a link's shadow underline, is composed into the backdrop: the text passes only when it meets the threshold over the plain backdrop and over the band, and fails when it does not. An accent link at 5.09 on paper over an 8 % ink underline band falls to 4.34 and fails (the CEO's choice: compute exactly).
- **One rule for every font stack.** A font-stack variable, like a literal `font-family` stack, must begin with an approved face; listed `fonts.fallback_families` and generic families may follow. A stack of generic families alone fails in both (the CEO's decision).

## Skills

| Skill | Owns | Use when |
|---|---|---|
| `starting-a-site-design-system` | the design-first path | a new site with no CSS yet |
| `keeping-a-site-design-system` | the site design folder: inventory, derivation, trace, token contrast, policy, waivers, approval, receipt | CSS or DESIGN.md changes; document or audit a site; add a token or component; the receipt is missing or stale |
| `building-in-a-site-design-system` | pages, panels, images, redesigns, the hand-over | an agent makes or changes a page for a site that has a design folder |

## The site design folder

`site.yaml`, `DESIGN.md`, `trace-map.yaml`, `contrast.yaml`, `policy.yaml`, `waivers.yaml`, `README.md`, and `ready.json`. It lives in the site's private repository, outside the deploy root. The owner approves it by committing it; `check_design.py --issue` then writes the receipt `ready.json` (the commit and the SHA-256 of every profile file, CSS file, plugin script and font), and the owner commits `ready.json` too. The page checkers refuse to check against a missing, invalid, stale or uncommitted receipt (INCOMPLETE); on a staged copy with no repository they need `--receipt-sha256` (the SHA-256 of the issued receipt, taken where the repository is).

**Trust model.** The owner's commit is the approval: for the profile files, and for the receipt with the CSS, script and font hashes it holds. Where a repository is reachable, every profile file and `ready.json` must equal its committed blob (compared with `git cat-file blob` after CRLF-to-LF only; a path whose attributes set `filter`, `ident` or `working-tree-encoding` is never approved, since the repository could change its content; Git runs only read-only plumbing, never a filter or a hook). An agent never commits (the working rules), so an edited sheet with an edited receipt stays uncommitted and INCOMPLETE. Committing `ready.json` does not make it stale: HEAD may be a later commit whose profile files are byte-equal to the receipt's commit.

## Scripts

| Script | Does | Doc |
|---|---|---|
| `check_design.py` | the design pair: DESIGN.md against the CSS; policy; boundary; approval and receipt | `scripts/docs/check_design.md` |
| `check_css.py` | the static role check of a page's own CSS; a report of hard-coded values | `scripts/docs/check_css.md` |
| `check_page.py` | a rendered page in a contained Chromium: assertions A1–A13 with axe-core | `scripts/docs/check_page.md` |
| `generate_css.py` | design-first: `tokens.css` and the trace map from DESIGN.md | `scripts/docs/generate_css.md` |
| `inventory_css.py` | the inventory that seeds a CSS-first profile | `scripts/docs/inventory_css.md` |
| `font_facts.py` | a font file's PostScript name, coverage and SHA-256 for the policy | `scripts/docs/font_facts.md` |

Shared modules: `designlib.py` (strict YAML and JSON, typed values, WCAG contrast, reports), `csslite.py` (the CSS grammar), `policylib.py` (profile, receipt, palette by role, gradients, waivers, output locations), `bundlelib.py` (the bundle guard, the one-read file reader and the reference resolver both page checkers use), `pagejs.py` (the JavaScript evaluated by the checker, never page scripts).

Outcomes of every checker: PASS 0, FAIL 1, ERROR 2, INCOMPLETE 3 (never a pass), INTERNAL 4.

## Running

- Linux and macOS: `python3 -I "<plugin root>/scripts/<script>.py" …`; Windows: `py -3 -I "<plugin root>\scripts\<script>.py" …`. The plugin root is two folders above a skill's base directory (in Claude Code also `${CLAUDE_PLUGIN_ROOT}`).
- Dependencies: Python 3.10+ and PyYAML for every script; Playwright for Python and its Chromium for `check_page.py` and the browser method of `font_facts.py`; fontTools optional (`font_facts.py`; WOFF2 needs brotli). A missing one gives ERROR naming it; nothing installs itself.
- Windows: install PyYAML for the Python that runs the scripts, without `--user` (`py -3 -m pip install PyYAML`), because `-I` ignores the user site-packages (found on the laptop, 2026-11-10).
- `check_page.py` as root on Linux needs `--run-as <unprivileged user>` (Chromium's sandbox refuses root); it then runs the browser in its own network namespace (`containment: os`). On Windows and macOS it uses `containment: browser`: every host and every other loopback port goes to a dead proxy and is routed off; only the checker's own origin is reachable. The environment variable `SDS_FORCE_BROWSER_CONTAINMENT=1` forces that level on Linux; it exists for the tests.

## Tests

`python3 -m pytest -q tests/` (about 740 tests). Synthetic sites X (light-only, accent, reserved token), Y (design-first, both schemes) and Z (dark-only) are built by `tests/sites.py`; the page tests use real OFL fonts from the system font folder and skip without them (and `check_page.py`'s entry-point runs skip without Playwright); as root they run the browser as user `claude`. `tests/test_page_analysis.py` checks `check_page.py`'s closure, guard, staging, child and analysis without a browser, on every platform. Mutants: `python3 tests/mutation/run_mutants.py` (results in `tests/mutation/last-results.txt`); a mutant whose killers need the browser, Linux or Windows is SURVIVED where they skip.

## Limits (0.1.0)

Paints judged by role: `color`, `background-color` and gradient stops (any spelling; an unreadable stop gives INCOMPLETE), border and outline colours, `box-shadow` and `text-shadow`, SVG `fill`, `stroke` and gradient `stop-color` (attributes included; a `url(#id)` paint's fallback colour is judged too, and one naming no gradient of the document gives INCOMPLETE), `-webkit-text-fill-color`, `-webkit-text-stroke-color`, `text-decoration-color`, `::first-line`/`::first-letter` colours. Computed colours in `color(srgb …)` and `color(srgb-linear …)` are converted exactly; any other space (`display-p3`, `lab()`, `oklch()`, …) gives an A2 floor INCOMPLETE, never a skip. Not judged by role: `accent-color`, `caret-color`, `column-rule-color`, `border-image`, `filter: drop-shadow()`, `::marker` colours, `text-emphasis-color` (keep them unset in new pages; A6 still gives INCOMPLETE where a border image or a drop-shadow may paint under text). Text in `::before`/`::after` content gets no contrast verdict (INCOMPLETE); A6's fallback passes a gradient only by a proved lower bound over every sRGB interval (`scripts/docs/check_page.md`), fails it at a real point below the threshold, and gives INCOMPLETE otherwise, for other interpolation spaces, translucent stops or translucent text over a gradient (no sample below the threshold), a faded group over its own background, beyond 512 backdrops, SVG text painted by a paint server, `context-fill`/`context-stroke` or a visible stroke; SVG text's `fill-opacity` is composed. **The checker changes no document it checks** (no attribute, element, stylesheet or text node; element identity stays in its scripts and CDP) and never resizes the viewport: it scrolls the main frame to the offsets that bring each text run of the page wholly into the viewport (at most 40 per render, up to 20,000 px) and takes each run's contrast, overlap and font evidence there; a run never wholly inside the viewport (taller than it, wider than it, below the limit, or in a child frame below that frame's own viewport) gives A6 INCOMPLETE "text not inside the checked viewport" and A1 INCOMPLETE. Every frame's paints (one list, `PAINT_PROPS`, for every comparison: colours, visibility, display, offsets, margins, `transform`, `scale`, `rotate`, `translate`, `clip`, `zoom`, `content-visibility`, `box-shadow`, borders and their radii, outlines, background size, position, repeat, clip and origin, padding, `width`, `height`, border images, `-webkit-box-reflect`, `accent-color`, `color-scheme`, text decorations, masks, overflow; for each rendered `::before` and `::after` too) are read first, at every scroll offset used and after all evidence: any difference (a scroll-driven animation, a sticky style that changes; also `content-visibility: auto` content and lazily loaded images without set sizes, whose `width` and `height` change as they scroll into view) gives every text run of that frame A6 INCOMPLETE, never a pass. **Paints hit testing never sees:** a `box-shadow`, `outline` or `border-image` of any element of the frame whose reach (measured where the run was checked, in viewport coordinates, so sticky and fixed boxes count where the reader sees them) meets the run gives it A6 INCOMPLETE: an inset shadow of the run's element or an ancestor, or of an element whose padding box meets the run; an outer shadow as the border box moved by its offset, grown by its spread and by 1.5 × its blur (Skia draws a Gaussian of deviation blur / 2 to three deviations) plus a pixel, minus the element's own rounded border box (used radii); an outline as its ring (a negative `outline-offset` draws it inside the box); a border image over the box grown by `border-image-outset`. A solid inset band (no blur) of the run's element or an ancestor is composed into the backdrop instead: the run passes only over the plain backdrop and over every combination of the bands, fails when one is below the threshold, and is INCOMPLETE with more than 4 band shapes, a band in a faded group, an animated painter, or text in a negative `z-index` layer beneath the band. A `blur()` or `drop-shadow()` filter of an element with no content of its own (no child elements, text, `::before`/`::after`, own shadow, outline or border image, SVG, replaced content or list marker) reaches its border box grown by 3 × blur (the deviation), or moved by the drop shadow's offset and grown by 1.5 × its blur, plus a pixel: only runs within that reach are INCOMPLETE (an animated filter: every run). Where the reach is not computed, every text run of the frame is INCOMPLETE: such a filter on any other element (ancestor or not) or a transformed one, a filter that cannot be read (an SVG filter `url()`), a `-webkit-box-reflect`, a box-shadow, outline, border image, filter or reflection of a `::before` or `::after`, an unreadable shadow value, and a shadow, outline or border image of an element that is (or whose ancestor is) transformed, zoomed or on a motion path. Not detected: a `text-shadow` of another element reaching the run (reported to HQ in TASK-CC-07); paints of a parent document over a child frame's text; a list item's `::marker` drawn under another element's text, and text in a negative `z-index` layer painted beneath an ancestor's opaque background (both reported to HQ in TASK-CC-08); a CSS animation or transition that is still running or waiting in its delay when the page is checked, and changes what lies under the text afterwards (for example an ancestor's background turning to the text's colour after ten minutes): A6 judges only the state it sees during the check (HQ's finding Z1, recorded as a limit by the owner's decision of 2026-11-12; build new pages without delayed animations of backgrounds under text). **Filters:** axe-core composes no CSS filter, so a `filter` or `backdrop-filter` on a text run's element or an ancestor gives A6 INCOMPLETE where axe passed it (the fallback already gave INCOMPLETE). Text in a child frame whose own document paints no opaque background beneath it gives A6 INCOMPLETE ("the backdrop lies outside the frame"), whatever axe says there. **Reader preferences:** the evidence is taken with reduced motion and no contrast or transparency preference (pinned by CDP); each render's page is then loaded again, fresh, in the 11 other combinations of `prefers-reduced-motion` (`reduce`, `no-preference`), `prefers-contrast` (`no-preference`, `more`, `less`) and `prefers-reduced-transparency` (`no-preference`, `reduce`), and a frame whose paints differ from the evidence page's first read in any of them gives its text A6 INCOMPLETE (a state not confirmed by `matchMedia` in its load: INCOMPLETE too); only A6 reads these loads, the other assertions judge the evidence state; `forced-colors: active` (and `prefers-contrast: custom`) is not emulated, since the user agent replaces the page's colours there, and device features (`hover`, `pointer`, `resolution`, other viewport sizes) are not varied. Text in an element with `display: contents` gives A6 and A1 INCOMPLETE (Chromium's axe and CDP give no result for it). A12 needs a result in every checked frame naming every rule axe-core 4.14.0 has for the selected tags (less `color-contrast` and, in a child frame, the rules about the top document). A13 compares the structure of the desktop light render only; its fields are credited to their owner (`element.form`). `check_css.py` expands at most 64 page-variable definitions per declaration, in every path that resolves one (more: INCOMPLETE), keeps each document's variables apart (a frame's or `srcdoc`'s own map), compares `color-mix()` results exactly (no rounding) and reads a `font` shorthand through a variable only when its family is exactly one certified font-stack variable (any other `var()` there: INCOMPLETE); a font-stack variable is certified only when every family of its value is an approved face, a generic family or a family listed in the optional `fonts.fallback_families` (a policy's allowed system fallbacks; A1 still judges the font that actually draws the text), and a literal `font-family` stack of a page's own CSS is accepted when its first family is an approved face and every other one passes the same test. Both page checkers keep at most 5,000 report items, failures first (in `check_css.py --report` the truncation line keeps the total). **Bundle paths:** one portable component grammar on every platform: a component ending in a dot or a space, holding `:` (streams, drives), `\ < > " | ? *` or a control character, a short 8.3 alias (`~` and a digit) or a Windows device name (`CON`, `NUL`, `COM1`, …) is refused before anything is opened; the bundle root is opened once and every file read relative to it (a root replaced during the run is refused); `url()` inside a CSS string is no reference, `<template>` content is not followed, and every SVG file of the closure is scanned for scripts. **The private renderer** (`check_page.py --_render`) serves only the staged inventory its job lists, each file sent only when its SHA-256 matches; it trusts its job, which only `check_page.py`'s parent writes, and gives no verdict. **Run limits:** the 120-second deadline counts from before staging; captures are viewport-sized (their pixel area bounded before capture), and the captures and the renderer's result share one 60 MB artefact budget; a capture's PNG is held in memory once before it is written; an oversized result keeps its A10 evidence (cut, with counts) and reports the rest INCOMPLETE. **P3:** `rem` uses the root font size the site sets on `html` or `:root` (the smallest across its media contexts; 16 px only when it sets none); an uncertain root size (a viewport unit, `clamp()`, a keyword, several values) takes the stricter 4.5:1 threshold; the smallest of a component's size and its trace-map font-size overrides is used. **P1:** an ambiguous or `!important` declaration anywhere in a bound variable's dependency graph gives INCOMPLETE. Static pages only (page scripts never run; a script, an inline handler, a `javascript:` URL or a meta refresh gives INCOMPLETE); no hover, focus or active states; raster images not checked; the trace is declaration-level, not the effective cascade (several different declarations of one binding give INCOMPLETE); `@supports`, `@layer`, `@container`, `@scope`, `@import` give INCOMPLETE; accessibility checks claim no WCAG conformance. `inventory_css.py` lists the properties named in its `PROPS` only. Third-party components: `THIRD-PARTY.md`.
